# Architecture

gitnote has no backend of its own. The user's git repo is the only place notes are
kept, the device holds a clone, and a stateless Cloudflare Worker fills the two gaps a
browser cannot: GitHub and GitLab do not answer git requests with CORS headers, and
GitHub's code exchange needs a client secret.

## Data flow

```text
Browser or Android WebView
  |-- static files ------------------> Static Assets (no Worker code runs)
  |-- REST: profile, repos, branches -> api.github.com, gitlab.com/api/v4 (direct, CORS)
  |-- GitLab sign-in (PKCE) ---------> gitlab.com (direct, CORS)
  |-- GitHub code and refresh -------> Worker /api/oauth/* --> github.com
  `-- git fetch and push ------------> Worker /api/git/*   --> github.com, gitlab.com
```

- **Clone and pull:** isomorphic-git runs on the device and fetches through the relay
  into LightningFS. The clone is shallow; later fetches pass no depth.
- **Edit:** text goes to a draft in IndexedDB on every change, to the working tree on
  save, and into git only on a commit.
- **Push:** the engine checks size limits first, then sends the pack through the relay.
  Offline, the push waits in a queue on the device.
- **Android** runs the same app in a WebView at `https://localhost` and calls the relay
  by its full address. See [android.md](android.md).

## Relay routes

Only `/api/*` runs the Worker; every other path is a static asset, with unknown paths
falling back to `index.html`. The `workers.dev` and preview hostnames are off, so the
app's own domain is the only origin.

| Route | Does |
| --- | --- |
| `GET /api/health` | Liveness probe |
| `GET /api/git/<host>/<repo path>.git/info/refs?service=git-upload-pack` (or `git-receive-pack`) | Git smart-HTTP ref discovery |
| `POST /api/git/<host>/<repo path>.git/git-upload-pack` and `.../git-receive-pack` | Fetch and push; needs `Content-Length`; body uncompressed or `Content-Encoding: gzip` (415 otherwise) |
| `POST /api/oauth/github/token` | GitHub App code exchange: JSON `{ code, code_verifier?, redirect_uri? }`, with `Content-Length` |
| `POST /api/oauth/github/refresh` | GitHub App token refresh: JSON `{ refresh_token }`, same limits |

- **Git hosts** come from the `GIT_HOSTS` var: `github.com,gitlab.com` over https.
  Loopback entries such as `localhost:8174` use http, for local test servers only.
  Other hosts, paths, methods and content types answer 403. github.com repos must be
  exactly `<owner>/<repo>.git`, and no path segment may be `-` (GitLab's web-route
  separator), so the relay never fetches a web page.
- **Responses.** A 2xx passes through only with the git content type for that endpoint
  (otherwise a JSON 502 `unexpected_upstream_response`), and an error status keeps its
  body only when it is `text/plain` (otherwise a JSON `upstream_error` with the same
  status). Every `/api/*` answer carries `X-Content-Type-Options: nosniff` and
  `Content-Security-Policy: default-src 'none'; sandbox; frame-ancestors 'none'`.
- **Headers.** Only `Authorization`, `Content-Type`, `Accept`, `Git-Protocol` and
  `User-Agent` go upstream, and a `User-Agent` that does not start with `git/` becomes
  `git/gitnote-relay`. Redirects are never followed: an upstream 3xx (a renamed repo)
  comes back as a JSON 502 `repo_moved`.
- **Origins.** `/api/*` answers the Worker's own origin and the origins in
  `CORS_ORIGINS` (`https://localhost`, the Capacitor WebView, which also gets CORS
  headers). Requests without `Origin` pass unless `Sec-Fetch-Site` says another site
  sent them. This stops browsers only; non-browser clients are bounded by the host
  allowlist and the rate limits.
- **Errors** are JSON: `{ "error": "<code>", "message": "..." }`.
- **Security headers** for the app live in `app/static/_headers`, because asset
  responses skip the Worker. The Content Security Policy is generated by SvelteKit
  (`csp` in `app/vite.config.js`) as a `<meta>` tag in the built `index.html`, so it
  also applies inside Capacitor. The Android build allows inline scripts for Capacitor's
  bridge, so it must never be deployed.

## Storage

| What | Where | Lifetime |
| --- | --- | --- |
| Clones, one per repo | IndexedDB through LightningFS, named `gitnote:<host>/<path>` | Until deleted in the app; the emptied database and its name stay until site data is cleared |
| Drafts | IndexedDB `gitnote-drafts` | Until saved or discarded |
| Web tokens | IndexedDB `gitnote-auth`, encrypted with a non-exportable AES-GCM key | Until sign-out |
| Android tokens | Android Keystore-backed secure storage | Until sign-out |
| Local copies list, queued pushes, in-progress sign-in | localStorage | Until replaced or finished |
| Merge in progress | `gitnote-merge.json` in the clone's git directory | Until the merge ends |
| Anything about users, on the server | Nothing: no KV, D1, R2 or Durable Objects; logs, traces, Tail Workers and Logpush off | Not applicable |

The Worker's only state is the rate limiter's counters, keyed by client IP.

## Limits

| Limit | Value | Enforced by |
| --- | --- | --- |
| File: warning | over 50 MB | Engine, before any network call |
| File: block on GitHub | over 100 MiB ([GitHub's limit](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)) | Engine |
| File: block on GitLab.com | over 95 MB (relay cap) | Engine |
| Push: block | over 95 MB, estimated from the blobs the unpushed commits add | Engine |
| Git request body | 95 MB, under the [100 MB Workers limit](https://developers.cloudflare.com/workers/platform/limits/); 413 above it | Relay |
| OAuth request body | 8 KB | Relay |
| Requests per client IP | 300 a minute on `/api/*`, 10 on `/api/oauth/*`, per Cloudflare location and approximate | Relay |
| Repo size: warning before a clone | over 300 MB | App |
| Note opened as text | up to 5 MB, valid UTF-8 | App |
| Network silence | 60 seconds ends a git request | Engine |

The push estimate leaves out trees and commits, so a push just under the cap can still
get a 413 from the relay, which is mapped to the same message. There is no cap on
downloads through the relay: Workers does not limit response bodies.

## Testing against the live site

`npm run e2e:live` runs `app/e2e/live/` against `https://gitnote.miti99.dev`, or
`GITNOTE_LIVE_URL`, with nothing stood in for.

- `smoke.live.js` needs no credentials: asset headers, the CSP, deep-link reloads, the
  relay's refusals, the Android preflight and a native `git clone` of this public repo.
- `notes.live.js` pastes a token, clones, edits, commits, pushes and pulls, checking
  each result directly against GitHub's API. It skips unless both `GITNOTE_E2E_REPO`
  (`<owner>/<repo>`) and `GITNOTE_E2E_TOKEN` are set. Use a private repo kept for this,
  with a seed commit on its default branch, and a fine-grained token scoped to that repo
  alone with Contents read and write. Each run moves its `gitnote-e2e` branch back to
  the default branch's tip; the default branch itself never changes.

In `.github/workflows/deploy.yml` the `live-e2e` job runs after each deploy and is
skipped while the `GITNOTE_E2E_REPO` repository variable is empty. A pull request can
never start it. It uploads no artifacts, because a Playwright trace would hold the
token.
